# 📑 Закладка

**Насколько хорошо ты знаешь книги?** Ежедневная игра: 10 вопросов вперемешку — книга по дурацкому пересказу, герой по подсказкам, обложка из эмодзи, выдуманное название среди настоящих. Около пяти минут, один выпуск в день — одинаковый для всех. Ниже на главной — отдельные режимы для разминки.

Фронтенд без бэкенда: React + TypeScript + Vite. Никаких аккаунтов, API и баз данных. Весь контент лежит в репозитории, прогресс — в `localStorage`. Работает на GitHub Pages.

```bash
npm install
npm run dev      # локальная разработка → http://localhost:5173
npm run check    # проверка типов и датасета вопросов
npm run build    # production-сборка в dist/
npm run preview  # посмотреть собранную версию
```

## Product spec

### Концепция
Лёгкая ежедневная игра на 3–7 минут для людей 18–35, которые не обязательно много читают, но хотят проверить: «А я вообще узнаю эту книгу?». Не учебник и не каталог. Юмор (пересказы голосом HR, Netflix и отзывов на маркетплейсе) + ощущение «я это знаю!» + результат, которым хочется поделиться.

### Core loop
1. Открыл сайт → одна большая кнопка «Начать игру».
2. 10 вопросов разных механик, от лёгких к сложным. После каждого — короткий факт.
3. Итоги: `8/10`, литературный уровень, сетка 🟩🟨🟥, очки, серия.
4. Поделиться результатом → завтра новый выпуск → серия 🔥 растёт.
5. Хочется ещё — «Разминка» по отдельным режимам (без ограничений).

Пользователю не нужно выбирать из 9 игр: главное действие одно. Режимы — вторичный слой для тех, кому мало.

### Режимы (что осталось и что изменено)

| Режим | Исходная идея | Решение |
|---|---|---|
| **Плохой пересказ** | A + B | Объединены: один режим, у каждого пересказа своя «плашка стиля» — плохой пересказ, AI-саммари, корпоративная рассылка, Netflix, стартап-питч, Telegram, вакансия, отзыв на маркетплейсе, Авито, дейтинг. Это фирменный режим — им открывается каждый выпуск. |
| **Одна фраза** | E | Первые строки и крылатые фразы. Только очень короткие фрагменты. |
| **Кто это?** | G | Персонаж по 3 подсказкам — от трудной к очевидной. Каждая подсказка стоит 30% очков: появляется выбор «рискнуть или подстраховаться». |
| **Автор под прикрытием** | I | Портретов нет (см. ниже) — автор угадывается по биографическим подсказкам, как персонаж. Поддержка портретов в коде оставлена. |
| **Обложка из эмодзи** | F | Настоящие обложки = авторские права + внешние картинки. Замена: «обложка» из трёх эмодзи на цветной книжке. Рендерится локально, не ломается, смешно. Текстовая расшифровка — платная подсказка. |
| **Найди выдумку** | K | Как есть. Лучшие вопросы — где настоящие названия звучат безумнее выдумки («Человек, который принял жену за шляпу»). |
| **Книга или кино** | H | Две механики с одинаковыми кнопками: «Что было раньше — книга или сразу сценарий?» (Шрек, Крепкий орешек, Иван Васильевич) и «Это было в книге или придумали для экрана?» (рубиновые туфельки, «Элементарно, Ватсон»). |
| **Хит или признание** | J | Только хрестоматийные случаи с известной историей публикации. |
| **Гонорар** | C + D | См. ниже. |

**Почему нет «угадай цену книги» и «угадай зарплату автора».** Живые цены требуют API и устаревают, а доходы большинства классиков неизвестны — пришлось бы выдумывать цифры. Вместо этого режим **«Гонорар»**: 
- «Что продали дороже?» — пары документированных аукционных продаж (Первое фолио Шекспира, Лестерский кодекс, «Птицы Америки», первое издание «Гарри Поттера»);
- хрестоматийные денежные истории писателей (Твен и наборная машина, «Игрок» за 26 дней, Чехов и Маркс, долги Пушкина, «Кэрри» из мусорного ведра).

**Почему нет «автора по фотографии».** Внешние хотлинки ломаются, а надёжно подготовить набор изображений в общественном достоянии для MVP не получилось. Механика превращена в «Автора под прикрытием», а в модели вопроса есть поле `image`: положите портрет (только public domain) в `public/portraits/` и добавьте `image: 'portraits/tolstoy.jpg'` — карточка покажет его над подсказками.

### Очки
- База: **100 / 200 / 300** за лёгкий / средний / сложный вопрос.
- **Серия ответов** умножает очки: ×1 → ×1,25 → ×1,5 → ×1,75 → максимум ×2. Ошибка сбрасывает.
- **⚡ Быстрый ответ** — +25%. Порог зависит от длины текста (5 с + время на чтение), чтобы длинные пересказы не наказывали.
- **Подсказки** (у героев и авторов, расшифровка эмодзи) — −30% базы каждая.
- **Идеальная игра** 10/10 — +500.

Главная цифра — `8/10`: её понятно показать другу. Очки — для личных рекордов.

**Литературный уровень:** Смотрел экранизацию → Читал краткое содержание → Читатель → Книжный червь → Библиотекарь → Живой классик.

### Игра дня
- Набор вычисляется из даты (`YYYY-MM-DD`, локальное время игрока) детерминированным генератором (`cyrb53` → `mulberry32`). Одинаковый у всех, без сервера.
- Слоты сложности: 3 лёгких → 4 средних → 3 сложных. Первый вопрос — всегда пересказ.
- Два вопроса одного режима не идут подряд, каждый режим — максимум 2 раза.
- Вопросы из выпусков последних 7 дней не повторяются (дни считаются последовательно от дня запуска — 26.09.2026, выпуск №1).
- Порядок вариантов ответа тоже детерминирован.
- Незаконченная игра сохраняется: refresh продолжает с того же вопроса. Сыграть выпуск можно один раз.

### Серия и заморозка
🔥 Серия = дни подряд с сыгранным выпуском. **❄ Заморозка** выдаётся за каждые 7 дней подряд (максимум одна): она спасает серию, если пропустить ровно один день. Это дёшево в реализации, но сильно снижает фрустрацию «пропустил день — потерял 40 дней» — главную причину, по которой бросают daily-игры.

### Рейтинг
Никакого фейкового глобального лидерборда. Вместо него **«Зал славы»**:
- личные рекорды (топ-10 выпусков по очкам);
- «Это лучше, чем X% твоих прошлых игр» — честный персональный перцентиль;
- серия и лучшая серия, точность по режимам, история с мини-сетками.

### Поделиться
```
📚 Закладка №12 — 8/10
🟩🟩🟨🟩🟥🟩🟩🟩🟥🟩
✦ 1 840 очков · 🔥 6
Сможешь лучше?
https://…
```
На телефоне — Web Share API, на десктопе — копирование в буфер (с fallback через `execCommand`). 🟨 — угадано с подсказкой.

### Достижения (16)
📖 Первая закладка · 💯 Без помарок · 🔥 Втянулся (3 дня) · 🗓 Неделя чтения · 🏛 Абонемент (30 дней) · 🐛 Книжный червь (100 верных) · 🕵️ Детектив (10 выдумок) · 🎭 Кастинг-директор (10 персонажей) · 🎬 Киноман · 🧠 Эрудит (5 сложных подряд) · 🔎 С первой подсказки · ⚡ Скорочтение · 🏆 Рекордсмен (3000 очков) · 🧭 Всеядный (все режимы) · 🎯 Тренировка (10 разминок) · 🌙 Полуночник.

### Что сознательно НЕ вошло в MVP
- Глобальный рейтинг, аккаунты, синхронизация между устройствами (нужен бэкенд).
- Портреты авторов и настоящие обложки (права и хостинг картинок).
- Генерация картинки-результата для сторис (canvas → PNG) — хороший следующий шаг.
- Архив прошлых выпусков для игры задним числом.
- Английская версия, тематические недели («неделя фантастики»), пользовательские вопросы.

## Как добавить вопрос

Откройте файл режима в `src/data/questions/` и допишите объект:

```ts
{
  id: 'retell-war-worlds',        // уникальный и неизменный
  type: 'retell',
  difficulty: 2,                   // 1 лёгкий, 2 средний, 3 сложный
  tag: 'Отзыв на маркетплейсе',    // необязательно: плашка стиля
  prompt: '★☆☆☆☆ Соседи с Марса. Шумят, жгут лучами...',
  options: ['Война миров', 'Марсианские хроники', 'Аэлита', 'Солярис'],
  answer: 'Война миров',           // строка, совпадающая с одним из options
  explanation: 'Короткий факт, который покажется после ответа.',
  book: 'Война миров',
  author: 'Герберт Уэллс',
}
```

Дополнительные поля: `clues` (подсказки для `character`/`author`), `emoji` (для `emoji`), `ask` (свой текст вопроса), `image` (картинка из `public/`), `fixedOrder` (не перемешивать варианты).

Затем `npm run check` — скрипт покажет количество вопросов по режимам и сложности и найдёт ошибки (повторяющиеся id, ответ не из вариантов и т. п.).

**Новый режим:** новый тип в `types.ts`, запись в `modes.ts` (+ `MODE_ORDER`), файл вопросов, строка в `questions/index.ts`. Если нужен особый вид карточки — ветка в `components/QuestionCard.tsx`.

> Добавление вопросов меняет состав будущих выпусков (а также сегодняшнего для тех, кто ещё не начал). Уже начатые и сыгранные игры хранят id вопросов и не ломаются. Не удаляйте и не переименовывайте id опубликованных вопросов — иначе в истории игрока пропадут разборы.

### Правила контента
- Основа — узнаваемая мировая и русская классика, не редкости.
- Пересказы и подсказки — свои тексты. Цитаты — максимум одна короткая фраза.
- Никаких выдуманных фактов. Числа — только проверяемые (аукционы, даты публикаций). Выдуманные книги в режиме «Найди выдумку» явно помечены в разборе.

## Деплой на GitHub Pages

В репозитории уже есть workflow `.github/workflows/deploy.yml`.

1. Запушьте код в ветку `main`.
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow сам выполнит `npm ci`, `npm run check`, `npm run build` и опубликует `dist/`. Адрес появится во вкладке Actions и в Settings → Pages (`https://<user>.github.io/<repo>/`).

Почему ссылки не ломаются:
- `base: './'` в `vite.config.ts` — все пути к ассетам относительные, сборка работает и в `/<repo>/`, и на своём домене;
- роутинг через hash (`#/play`, `#/stats`) — refresh любой страницы не даёт 404;
- шрифты подключены локально через `@fontsource`, внешних запросов нет.

Вручную (без Actions): `npm run build` и загрузите содержимое `dist/` в ветку `gh-pages` (например, `npx gh-pages -d dist`), затем выберите эту ветку в Settings → Pages.

Свой домен: положите файл `public/CNAME` с доменом.
